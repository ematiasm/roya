{# The supplier picker (purchases-create-and-header T2) and its split from the results body. This macro is the widget: one supplier field that searches as you type over `GET /web/supplier-search`, exactly the product picker's htmx shape (partials/product_search_results.html) — a debounced `hx-get`, a bounded results fragment and no JavaScript: choosing a result posts the caller's target directly. The widget and the results body are separate templates because the results are answered by the search endpoint, not rendered by the host page: the endpoint re-renders the list on every keystroke while the field keeps its own markup. The macro takes the caller's context so two hosts share it unchanged (locked decision 3: one picker, two hosts — T3's creation dialog and T4's inline header): - `action` the caller's post target (the result forms post here too); - `target` the region the caller's post swaps back (`hx-select`ed); - `field_id` the text input's id, so the caller can label and reach it; - `current_name` the current supplier's name rendered into the field as a real, editable value (T3's last-used supplier, T4's stored one): the field's TEXT is the contract — the picker's own form posts only `supplier_name`, which resolves server-side (`resolve_supplier_name`, exact and case/diacritic-insensitive against a UNIQUE `suppliers.name`), so Enter, the submit button and an accepted pre-fill all create the RIGHT supplier. No hidden id rides in this form: an id wins only where the operator explicitly clicked a result, whose own form carries its `supplier_id` (partials/supplier_search_results.html); - `include` the caller's other field(s) the posts must carry (T3's date and notes), passed through to the results so a clicked result submits the same fields; empty when the caller has none. The results container is a sibling of the form because a form inside a form is invalid HTML — the product picker's stated reason. #} {% macro supplier_picker(action, target, field_id, current_name, include) %} {# Inheritance audit (the product picker's documented trap): the form's hx-target/hx-swap/hx-select leak into the field, and the inherited hx-select would filter the search GET to an element the results fragment does not contain, leaving the results permanently empty in a browser (no HTTP test can see that). The form disinherits those attributes; the field keeps its own hx-target/hx-swap and inherits no hx-select. #}
