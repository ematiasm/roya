{# Product search results and the shared line picker (redesign-interface N4). This file holds both halves of one widget: 1. `line_picker` is the record page's product field: one input matches name, SKU and barcode at once, the USB reader types into it and Enter submits. The sale and the purchase record pages import this one definition and pass their own line endpoint, money region, price field and price context. 2. The results body answers `GET /web/product-search?q=` with name, SKU and current stock. When the caller supplies the record's line action and swap target, every match becomes its own add form: the request includes `#line-picker` (so the quantity travels) and supplies its own product_id through `hx-vals`. The results container is a sibling of the picker form because a form inside a form is invalid HTML. `price` says which number the calling context works in: `cost` for a purchase line, `sale` (the default) for a sale line. Only that price is shown, so the picker never mixes what the shop pays with what it charges. Accessibility: `#product-search-results` is the polite live region (set in the picker macro). Only the hidden count is announced; the visual list sits under `aria-live="off"`, so typing does not read the catalogue out loud on every keystroke. The picker input describes itself with this status through `aria-describedby`. #} {% macro line_picker(oob, resource, id, money_target, price_field_id, price_field_name, price_label, price_placeholder, price_kind) %} {# Inheritance audit (htmx 1.9.12). htmx resolves most `hx-*` attributes by walking up from the element, so this form's attributes leak into every control inside it. What inherits (`getClosestAttributeValue`): hx-target, hx-swap, hx-select, hx-select-oob, hx-confirm, hx-prompt, hx-encoding, hx-params, hx-push-url, hx-replace-url, hx-sync, hx-boost; list values hx-include, hx-indicator, hx-disabled-elt; merged values hx-vals, hx-vars, hx-headers. What does not: the verb (hx-get/post/put/patch/delete), hx-trigger and hx-on are own-only. Here that meant `#product-picker` inherited hx-select="{{ money_target }}" and its own search GET was filtered to an element the search fragment does not contain, so the results container stayed permanently empty in a browser (no HTTP test can see that). `#line-qty` and the price input inherited hx-target/hx-swap/hx-select the same way; they are inert today only because a verb and hx-trigger are not inherited, so the next `hx-get`/`hx-trigger` added there would silently borrow the add-line request. The fix is therefore class-level, not instance-level: the form states which of its request attributes children must not inherit. `#product-picker` keeps its own hx-target/hx-swap, and the qty and price inputs inherit nothing at all. #}
